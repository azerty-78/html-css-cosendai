1) C'est quoi JavaScript ?
JavaScript est un langage de programmation principalement utilisé pour rendre les pages web interactives.
  • Créé en 1995 par Brendan Eich (Netscape).
  • Standardisé sous le nom ECMAScript (ES) par l'ECMA.
  • Utilisé côté navigateur et aussi côté serveur (Node.js).

3) Quel type de langage ?
JavaScript est un langage dynamique, interprété, multi-paradigme, exécuté par un moteur (V8, SpiderMonkey, JavaScriptCore).
  • Langage à typage dynamique (faible) : le type d'une variable peut changer selon la valeur.
  • Multi-paradigme : procédural, orienté objet, fonctionnel.
  • Interprété + compilé JIT : le moteur JS lit le code et optimise/compile à la volée.
  • Single-thread + event loop : un seul thread principal pour le code JS, avec file d'attente des événements.
let x; typeof x; // "undefined" x = 12; typeof x; // "number" x = "Bonjour"; typeof x; // "string"
Compilateur : à quoi il sert ? Un compilateur traduit du code source en une forme exécutable ou optimisée. En JavaScript moderne, le moteur utilise une compilation JIT (Just-In-Time) : il compile au moment de l'exécution les parties "chaudes" du code pour accélérer les performances. À côté de ça, des outils comme Babel/TypeScript peuvent aussi "compiler/transpiler" le code avant exécution pour compatibilité ou sécurité de typage.
4) JavaScript, HTML et CSS : qui fait quoi ?
  • HTML : structure de la page (titres, paragraphes, formulaires...).
  • CSS : présentation (couleurs, tailles, mise en page, animations).
  • JavaScript : comportement (clics, validation, affichage dynamique, appels API).
<h1 id="titre">Bonjour</h1> <script> document.getElementById("titre").textContent = "Bonjour JavaScript"; document.getElementById("titre").style.color = "royalblue"; </script>
5) Le DOM (Document Object Model)
Le DOM représente la page HTML sous forme d'arbre d'objets manipulables par JavaScript. Chaque balise devient un nœud avec des propriétés, des méthodes et des événements.
  • Accéder : `getElementById`, `querySelector`, `querySelectorAll`
  • Modifier : `innerHTML`, `textContent`, `style`, `className`
  • Créer/Supprimer : `createElement`, `appendChild`, `removeChild`
  • Naviguer : `parentNode`, `children`, `firstElementChild`, `nextElementSibling`
  • Réagir : `addEventListener` (click, input, submit, keydown...)
const titre = document.getElementById("titre"); titre.textContent = "Titre modifié"; titre.style.color = "royalblue"; const p = document.createElement("p"); p.textContent = "Nouveau paragraphe"; document.body.appendChild(p);
Bonnes pratiques DOM : limiter les modifications répétées, regrouper les mises à jour, éviter d'utiliser `innerHTML` avec du contenu non fiable (risque XSS).
6) JSON, XML et échange de données
JSON et XML sont des formats d'échange. JavaScript manipule très naturellement JSON car sa structure ressemble aux objets JS.
  • JSON (JavaScript Object Notation) : format texte léger, très utilisé avec APIs.
  • XML : format plus verbeux, historique, encore utilisé dans certains systèmes.
  • JSON impose des guillemets doubles pour les clés/chaînes, sinon `JSON.parse` échoue.
  • XML est basé sur des balises imbriquées, avec schéma possible (XSD) dans certains contextes métier.
// JSON: texte -> objet const txt = '{"nom":"Sara","age":20}'; const obj = JSON.parse(txt); // objet -> JSON const txt2 = JSON.stringify(obj); // formatage lisible const pretty = JSON.stringify(obj, null, 2);
FormatLisibilitéTailleUsage actuel

Quand choisir ? JSON pour la majorité des APIs web modernes. XML quand l'écosystème l'impose (anciens SI, flux métier spécifiques, SOAP).
7) AJAX et communication serveur
AJAX (Asynchronous JavaScript and XML) permet d'envoyer/recevoir des données sans recharger toute la page. Aujourd'hui, on utilise surtout JSON et `fetch`.
  • Ancien objet : `XMLHttpRequest`
  • Approche moderne : `fetch` + `Promise` + `async/await`
  • Cycle classique : requête → réponse → mise à jour du DOM
  • Souvent utilisé avec JSON
  • Gestion importante : erreurs réseau, timeout, code HTTP (`200`, `404`, `500`...)
fetch("/api/etudiants") .then(r => { if (!r.ok) throw new Error("HTTP " + r.status); return r.json(); }) .then(data => console.log(data)) .catch(err => console.error(err));
// Même logique avec async/await async function chargerEtudiants() { try { const r = await fetch("/api/etudiants"); if (!r.ok) throw new Error("Erreur HTTP"); const data = await r.json(); console.log(data); } catch (e) { console.error(e.message); } }
8) Environnement d'exécution
  • Navigateur : Chrome (V8), Firefox (SpiderMonkey), Safari (JavaScriptCore).
  • Node.js : JS côté serveur, scripts, outils, backend.
  • Le code peut être débogué via la console DevTools (F12).
9) Comment coder en JavaScript et l'intégrer en HTML
JavaScript peut être écrit directement dans une page HTML ou dans un fichier externe. En pratique professionnelle, on préfère les fichiers externes pour garder un code propre et maintenable.
  • Inline (peu recommandé) : JS directement dans un attribut HTML, utile pour de très petits tests.
  • Script interne : bloc <script> dans la page, souvent en bas du <body>.
  • Script externe (recommandé) : fichier `.js` séparé, importé avec `src`.
  • Le navigateur lit le HTML, puis exécute le JS au moment de rencontrer <script> (d'où l'intérêt de defer).
// 1) Script interne (dans le HTML) <script> const titre = document.querySelector("h1"); titre.textContent = "Bonjour JS"; </script> // 2) Script externe (recommandé) <script src="app.js" defer></script>
Bon réflexe : placer le script avec `defer` dans le `` ou en bas du `` pour éviter de bloquer le rendu HTML et garantir que le DOM est disponible.
10) Debouches, usages professionnels et evolution
JavaScript est l'un des langages les plus demandés. Il sert aujourd'hui dans presque toutes les couches d'une application moderne.
  • Frontend web : interfaces interactives, SPAs, dashboards, animations.
  • Backend : APIs et serveurs avec Node.js (Express, NestJS, Fastify...).
  • Mobile : React Native, Ionic (applications multiplateformes).
  • Desktop : Electron (apps bureau cross-platform).
  • Full-stack : même langage côté client et serveur (gain de productivité équipe).
Comment les frameworks utilisent JS ? Ils organisent le code, structurent les composants, optimisent le rendu UI, gèrent l'état et le routage, et facilitent les tests/maintenances.

11) Résumé
  • JS rend les pages web interactives.
  • C'est un langage dynamique, multi-paradigme, exécuté par un moteur avec optimisation JIT.
  • Le compilateur (ou transpileur) sert à traduire/optimiser le code pour l'exécution et la compatibilité.
  • Il manipule HTML/CSS via le DOM pour créer des interfaces dynamiques.
  • Il échange des données avec le serveur via AJAX/fetch, majoritairement en JSON.
  • Il fonctionne côté client (navigateur) et côté serveur (Node.js).
Ordre conseillé pour ce parcours : bases → contrôle du flux → fonctions/objets → DOM/événements → AJAX/JSON.
